# Данные квартир

Каталог хранится отдельно от компонентов интерфейса.

- `apartments.json` — ровно 30 квартир из 15 городов России.
- `apartment-layouts.json` — типы помещений, доли площади и базовая геометрия комнат на SVG-плане.

Каждая квартира содержит `city` и связывается с планировкой через `layoutId`. Комнаты не дублируются в каждой квартире: они описываются один раз в планировке. Площадь помещения рассчитывается по `areaShare` от общей площади квартиры.

## Форматы геометрии

Прямоугольная комната:

```json
{
  "kind": "rect",
  "x": 58,
  "y": 58,
  "width": 240,
  "height": 180
}
```

Ломаная, Г-образная или скошенная комната:

```json
{
  "kind": "polygon",
  "points": [
    { "x": 58, "y": 58 },
    { "x": 300, "y": 58 },
    { "x": 300, "y": 150 },
    { "x": 250, "y": 150 },
    { "x": 250, "y": 238 },
    { "x": 58, "y": 238 }
  ],
  "labelX": 160,
  "labelY": 140
}
```

`labelX` и `labelY` необязательны. Если их нет, приложение само ищет безопасную точку внутри полигона.

## Как формируется визуальный план

JSON остаётся источником состава помещений и базовой геометрии. Визуальный слой применяет к схеме детерминированную вариацию по `apartment.id`:

- зеркальное отображение или поворот;
- небольшое смещение общих линий стен;
- Г-образные помещения и ступенчатые внутренние перегородки;
- ниши и углубления внешнего контура;
- разные пропорции прихожей, мокрой зоны и жилых комнат;
- двери и окна, привязанные к реальным сегментам полигонов;
- различное остекление лоджий;
- кухонная линия, сантехника, встроенные шкафы, вентиляционные шахты и колонны.

Смежные комнаты получают одну и ту же ломаную линию общей стены, поэтому между ними не появляются щели и наложения. Внешний контур строится из фактических наружных сегментов всех полигонов, а не из общего прямоугольника.

Это не случайная генерация при каждой загрузке: одна квартира всегда получает одну и ту же схему. Поэтому ссылки, расстановка мебели и выбор комнат остаются стабильными.

Требования к базовой планировке:

- сумма `areaShare` должна быть равна `1`;
- координаты должны находиться внутри рабочей области `x: 58–728`, `y: 58–538`;
- полигон должен содержать минимум три точки и не должен самопересекаться;
- соседние комнаты должны использовать одинаковые координаты общей стены;
- `roomId` внутри одной планировки должны быть уникальными;
- тип комнаты должен соответствовать типам из `types/apartment.ts`.

`lib/apartments.ts` проверяет количество квартир, уникальность ID, наличие планировки, минимум точек полигональной комнаты и сумму долей площадей. При ошибке сборка останавливается до публикации некорректного каталога.

Чтобы добавить квартиру:

1. Добавьте объект в `apartments.json` и укажите город и `layoutId`.
2. Используйте существующую планировку или создайте новую в `apartment-layouts.json`.
3. Для сложной формы используйте `kind: "polygon"` и массив `points`.
4. Проверьте общие границы соседних комнат.
5. При изменении количества объектов обновите проверку `EXPECTED_APARTMENT_COUNT`.
6. Запустите `npm run check`.
