# Данные квартир

Каталог хранится отдельно от компонентов интерфейса.

- `apartments.json` — ровно 30 квартир из 15 городов России.
- `apartment-layouts.json` — типы помещений, доли площади и базовые координаты комнат на SVG-плане.

Каждая квартира содержит `city` и связывается с планировкой через `layoutId`. Комнаты не дублируются в каждой квартире: они описываются один раз в планировке. Площадь помещения рассчитывается по `areaShare` от общей площади квартиры.

## Как формируется визуальный план

JSON остаётся источником состава помещений и базовой геометрии. `lib/apartment-plan-visuals.ts` применяет к базовой схеме детерминированную вариацию по `apartment.id`:

- зеркальное отображение или поворот;
- небольшое смещение общих линий стен без появления щелей и пересечений;
- разные пропорции прихожей, мокрой зоны и жилых комнат;
- смещённые двери и окна;
- различное остекление лоджий;
- кухонная линия, сантехника, встроенные шкафы, вентиляционные шахты и колонны.

Это не случайная генерация при каждой загрузке: одна квартира всегда получает одну и ту же схему. Поэтому ссылки, расстановка мебели и выбор комнат остаются стабильными.

Требования к базовой планировке:

- сумма `areaShare` должна быть равна `1`;
- координаты должны находиться внутри рабочей области `x: 58–728`, `y: 58–538`;
- соседние комнаты должны использовать одинаковые координаты общей стены;
- `roomId` внутри одной планировки должны быть уникальными;
- тип комнаты должен соответствовать типам из `types/apartment.ts`.

`lib/apartments.ts` проверяет количество квартир, уникальность ID, наличие планировки и сумму долей площадей. При ошибке сборка останавливается до публикации некорректного каталога.

Чтобы добавить квартиру:

1. Добавьте объект в `apartments.json` и укажите город и `layoutId`.
2. Используйте существующую планировку или создайте новую в `apartment-layouts.json`.
3. Проверьте общие границы соседних комнат.
4. При изменении количества объектов обновите проверку `EXPECTED_APARTMENT_COUNT`.
5. Запустите `npm run check`.
