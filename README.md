# Homelix

Федеральный демонстрационный каталог квартир на Next.js 16 и React 19. Проект показывает 30 квартир в городах России, интерактивные SVG-планировки, подбор мебели, личный кабинет, избранное, бронирование и локального цифрового консультанта.

## Возможности

- 30 квартир из разных городов России;
- фильтр по городу и сортировка по цене, площади, этажу, комнатности и ипотечному платежу;
- постепенная загрузка карточек по 12 объектов;
- интерактивные планировки из `data/apartment-layouts.json`;
- каталог квартир из `data/apartments.json`;
- русский, английский и китайский интерфейсы главной страницы;
- личный кабинет, избранное и демонстрационное бронирование;
- магазин мебели и размещение мебели на плане;
- локальный rule-based консультант по каталогу и выбранной комнате.

## Важное ограничение

AI-роуты `/api/ai` и `/api/chat` сейчас не вызывают OpenRouter или другую внешнюю LLM. Они формируют предсказуемые ответы на сервере по данным каталога. Это сделано специально, чтобы демонстрация не зависела от стороннего ключа и не создавала неожиданные расходы.

Цены, статусы и наличие квартир являются демонстрационными. Перед реальной продажей их необходимо получать из CRM или промышленной базы данных и подтверждать менеджером.

## Безопасность

- пароли хэшируются `scrypt` с индивидуальной случайной солью;
- сравнение хэшей выполняется через `timingSafeEqual`;
- старые SHA-256-хэши автоматически заменяются при успешном входе;
- сессия хранится в `HttpOnly`, `Secure` (в production), `SameSite=Lax` cookie;
- срок сессии — 7 дней;
- выход отзывает сессию на сервере;
- auth и AI endpoints защищены временным IP rate limit;
- `/api/chat` принимает только ID квартиры и комнаты, а данные получает из серверного каталога;
- `/api/health` не раскрывает ключи, модель, host и origin;
- добавлены CSP, защита от iframe, `nosniff`, Referrer Policy и Permissions Policy;
- персональные рекомендации не пишут историю в localStorage до явного согласия.

Встроенный rate limit и блокировка JSON-хранилища работают на уровне одного Node.js-инстанса. Для нескольких serverless-инстансов нужны внешние Redis/Postgres и ограничения на уровне инфраструктуры.

## Хранение данных

Каталог и пользовательские данные разделены:

- `data/apartments.json` — квартиры;
- `data/apartment-layouts.json` — комнаты, доли площади и координаты планов;
- `data/database.json` — локальное демонстрационное хранилище пользователей, сессий, избранного и броней;
- `database/schema.sql` — схема PostgreSQL для промышленного внедрения.

Для локального запуска запись идёт в `data/database.json`. Путь можно переопределить переменной:

```env
HOMELIX_DATABASE_PATH=/persistent-volume/homelix-database.json
```

На Vercel локальная файловая система эфемерна. Для реального проекта необходимо подключить PostgreSQL/Supabase и перенести операции пользователей и броней на транзакции внешней БД. До этого авторизация и бронирование остаются демонстрационными.

## Запуск

Требуется Node.js 24.

```bash
npm ci
npm run dev
```

Сборка:

```bash
npm run build
npm start
```

Для проверки с другого устройства в локальной сети:

```bash
npm run dev -- --hostname 0.0.0.0
```

Разрешённые dev origins задаются через окружение, личные IP в репозитории не хранятся:

```env
ALLOWED_DEV_ORIGINS=localhost,127.0.0.1,192.168.1.20
```

## Основные страницы

```text
/                     каталог и жилые комплексы
/en                   английская версия главной
/zh                   китайская версия главной
/apartment/[id]       квартира и интерактивный план
/ai                   общий консультант
/furniture            магазин мебели
/account              аккаунт, избранное и бронирования
/api/health           минимальная проверка доступности API
```

## Переменные окружения

```env
NEXT_PUBLIC_SITE_URL=http://localhost:3000
ALLOWED_DEV_ORIGINS=localhost,127.0.0.1
HOMELIX_DATABASE_PATH=./data/database.json
```

`OPENROUTER_API_KEY` в текущей версии не используется.

## Что требуется перед production

1. Подключить PostgreSQL/Supabase и заменить файловое пользовательское хранилище.
2. Добавить распределённый rate limit, например Redis/Upstash.
3. Добавить email-провайдера и безопасный сброс пароля.
4. Перенести каталог и статусы из JSON в CRM/БД.
5. Добавить автоматические тесты авторизации, бронирования и API.
6. Настроить мониторинг ошибок и аудит действий менеджеров.
