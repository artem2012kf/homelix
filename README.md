# ХОЛЛ

Федеральный демонстрационный маркетплейс квартир на Next.js 16 и React 19. ХОЛЛ объединяет каталог новостроек по России, выбор города и жилого комплекса, интерактивные полигональные планировки, мебель с доставкой, личный кабинет, бронь и заявки на покупку.

## Возможности

- 30 квартир в 15 городах России;
- обязательный выбор города и жилого комплекса при первом посещении;
- рекомендации, карта, квартиры и офис продаж ограничиваются выбранным городом;
- фильтры в формате выбора этажей: комнатность, конкретный этаж, площадь, цена, статус и ЖК;
- ломаные планировки с Г-образными комнатами, нишами, выступами и ступенчатым внешним контуром;
- спокойная минималистичная цветовая гамма планов;
- русский и английский интерфейсы; китайская локализация удалена;
- английские цены отображаются в долларах по обновляемому курсу с резервным значением;
- мебель можно добавить в корзину, выбрать квартиру доставки и увидеть стоимость и срок;
- отдельные заявки на покупку квартиры и заказ мебели;
- круглая кнопка интерактивной карты выбранного города;
- личный кабинет с избранным, бронями, корзиной и выбранным городом;
- регистрация только после подтверждения владения почтой шестизначным кодом;
- изображения через `next/image` отдаются в AVIF, если формат поддерживается браузером.

## Подтверждение почты

Перед регистрацией сервер:

1. проверяет формат адреса;
2. проверяет наличие MX-записей почтового домена;
3. отправляет шестизначный код через Resend;
4. создаёт аккаунт только после проверки подписанного кода.

Проверка MX не доказывает существование конкретного ящика. Именно ввод кода из письма подтверждает, что пользователь владеет указанным адресом.

Для production необходимо указать:

```env
HOMELIX_AUTH_SECRET=replace-with-a-long-random-secret
RESEND_API_KEY=re_xxxxxxxxx
EMAIL_FROM=ХОЛЛ <no-reply@example.com>
```

Локальный демо-код можно включить только для закрытой разработки:

```env
HOMELIX_ALLOW_EMAIL_VERIFICATION_PREVIEW=true
```

Не включайте эту настройку на публичном сайте.

## Курс валюты

Английская версия запрашивает курс RUB/USD через серверный endpoint `/api/exchange-rate`. Источник можно заменить переменной окружения:

```env
EXCHANGE_RATE_URL=https://open.er-api.com/v6/latest/RUB
RUB_PER_USD_FALLBACK=90
```

При недоступности источника используется резервный курс. Стоимость в рублях остаётся исходной ценой каталога.

## Карта и офисы продаж

`lib/city-data.ts` хранит координаты, телефоны и адреса офисов для 15 городов. Сейчас это демонстрационные данные. Перед реальными продажами адреса и телефоны должны быть заменены подтверждёнными данными компании.

Карта использует встраиваемую OpenStreetMap и поддерживает перемещение и масштабирование.

## Покупки и корзина

Корзина мебели хранится в браузере. Заявки отправляются через `/api/purchase` и требуют авторизации. В демонстрационной версии заявки записываются в файловое/in-memory хранилище. Для production необходимо подключить CRM или PostgreSQL и перенести туда:

- заявки на квартиры;
- заказы мебели;
- статусы обработки;
- данные доставки;
- историю действий менеджеров.

## Важное ограничение

AI-роуты `/api/ai` и `/api/chat` сейчас не вызывают внешнюю LLM. Они формируют предсказуемые ответы по данным каталога. Цены, статусы, офисы и наличие квартир являются демонстрационными и должны подтверждаться менеджером.

## Безопасность

- пароли хэшируются `scrypt` с индивидуальной солью;
- сессия хранится в `HttpOnly`, `Secure` в production и `SameSite=Lax` cookie;
- срок сессии — 7 дней;
- выход и смена пароля отзывают серверные сессии;
- auth, AI, purchase и email endpoints защищены rate limit;
- reset-токены и коды подтверждения не хранятся в открытом виде;
- `/api/chat` принимает ID квартиры и получает данные из серверного каталога;
- `/api/health` не раскрывает секреты;
- настроены CSP, защита от iframe, `nosniff`, Referrer Policy и Permissions Policy;
- персональные рекомендации включаются только после согласия.

Встроенные rate limit и файловые блокировки работают только в пределах одного Node.js-инстанса. Для нескольких serverless-инстансов нужны Redis и PostgreSQL.

## Хранение данных

- `data/apartments.json` — 30 квартир;
- `data/apartment-layouts.json` — помещения и базовая геометрия планов;
- `lib/polygon-floor-plans.ts` — детерминированные ниши, выступы, ломаные стены и внешний контур;
- `data/database.json` — локальные пользователи, сессии, избранное и брони;
- `lib/purchase-store.ts` — демонстрационные заявки на покупку и мебель;
- `database/schema.sql` — основа PostgreSQL-схемы.

## Запуск

Требуется Node.js 24.

```bash
npm ci
npm run dev
```

Проверка и сборка:

```bash
npm run check
npm start
```

## Основные страницы

```text
/                     каталог и ЖК выбранного города
/en                   английская версия с ценами в USD
/apartment/[id]       квартира и интерактивная планировка
/ai                   консультант
/furniture            мебель, корзина и доставка
/account              кабинет, избранное, брони и регистрация
/api/exchange-rate    обновляемый курс RUB/USD
/api/purchase         заявки на квартиру и мебель
/api/health           минимальная проверка API
```

## Что требуется перед реальными продажами

1. Подключить PostgreSQL/Supabase и CRM вместо файлового хранилища.
2. Добавить распределённый rate limit через Redis/Upstash.
3. Указать production-домен и подтвердить домен отправителя в Resend.
4. Заменить демонстрационные офисы, цены и статусы на реальные данные.
5. Интегрировать платёжный провайдер, договоры и юридический сценарий покупки.
6. Добавить автоматические e2e-тесты регистрации, корзины, покупки и бронирования.
